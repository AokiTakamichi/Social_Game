# Social Game Jam - Game Balance Simulator

アナログゲーム「キャリア × ファンタジー」のゲームバランスを検証するための
モンテカルロシミュレーターです。

複数人のプレイヤーが職業ごとに行動して共有資金を稼ぎ、
15ターン以内に城を5段階建築できるかをシミュレーションします。

テストプレイで特定の行動（宝くじ）にゲーム展開が偏ったため、
確率・収入・体力・昇格などのパラメータを調整しながら
ゲームバランスを検証する目的で作成しました。

## ゲーム概要

- 想定プレイ人数：3～6人
- 最大ターン数：15ターン
- 所持金：パーティ共有
- 城の建築：5段階
- 勝利条件：15ターン以内に城を完成させる

### 城の建築費

| 段階 | 建築費 |
|---|---:|
| 1 | 100,000円 |
| 2 | 200,000円 |
| 3 | 300,000円 |
| 4 | 400,000円 |
| 5 | 500,000円 |

建築判定の初期成功率は50%です。

- 成功：建築費を全額消費して進捗+1
- 失敗：建築費の半額を失う
- 1ターンにつき最大1段階建築可能

これらの値はUIから変更できます。

## 主な機能

- Monte Carlo法によるゲームシミュレーション
- プレイヤー人数・職業構成の変更
- 最大ターン数の変更
- 各段階の建築費変更
- 建築成功率・失敗時損失率の変更
- 各職業の成功率・収入・消費体力の変更
- 宝くじ・散歩・ドカ寝などの休みイベント調整
- 昇格成功率・昇格解禁ターンの調整
- 通常職と上級職の収入比較
- 商人の所持金倍率・遅延効果のシミュレーション
- 騎士による最大体力上昇
- 乱数シードによる再現可能なシミュレーション

## 行動AI

プレイヤーの行動選択には以下の2種類があります。

### 即時期待値最大化

そのターンに得られる期待収入が最も高い行動を選択します。

### 残りターン期待総収入最大化

各候補行動について残りターンを仮想的にシミュレーションし、
ゲーム終了までの期待総収入が最大になる行動を選択します。

これにより、

- ドカ寝による体力回復
- 昇格による上級行動
- 商人の遅延投資

など、直接収入が発生しない行動の将来的な価値も評価できます。

期待値が同じ場合はランダムに行動を選択します。

## 休みイベント

働けるだけの体力がない場合、休みます。

まず体力を2回復した後、休みイベントを選択します。

初期設定では以下のイベントがあります。

| イベント | 効果 |
|---|---|
| 宝くじ | 1/6で300,000円 |
| 散歩 | 1/2で10,000円 |
| ドカ寝 | 追加で体力+2 |
| 昇格 | 条件達成後に昇格判定 |

宝くじの確率や当選額などはUIから変更可能です。

## 昇格

初期設定では第6ターン以降に昇格へ挑戦できます。

- 初期成功率：2/6
- 成功後：上級職の行動を使用

昇格成功率や上級行動の性能もUIから変更できます。

## シミュレーション結果

以下のような統計を確認できます。

- ゲームクリア率
- 平均クリアターン
- クリアターン分布
- ターンごとの平均所持金
- 平均建築進捗
- 各建築段階への到達率
- 建築成功・失敗回数
- 各職業行動の選択回数
- 各職業の平均収入
- 宝くじ選択回数
- 宝くじ当選回数
- 宝くじによる総収入
- 総収入に占める宝くじ収入割合
- 昇格挑戦率
- 昇格成功率
- 平均昇格ターン
- 通常職と上級職の平均収入比較

宝くじや昇格の確率を複数パターンまとめて比較することもできます。

## インストール

リポジトリをクローンします。

```bash
git clone <repository-url>
cd Social_Game_Jam
```

必要なライブラリをインストールします。

```bash
pip install -r requirements.txt
```

## 起動方法

以下を実行します。

```bash
python -m streamlit run app.py
```

起動後、ブラウザで表示されたLocal URLを開きます。

通常は以下です。

```text
http://localhost:8501
```

8501番ポートが使用中の場合は、8502など別のポートが使用されます。

## シミュレーションの基本的な使い方

1. プレイヤー人数を設定
2. 各プレイヤーの職業を設定
3. 試行回数を設定
4. 宝くじ・昇格・建築などのパラメータを設定
5. シミュレーションを実行
6. クリア率や収入構成を確認
7. パラメータを変更して再度比較

最初は少ない試行回数で動作確認し、
最終的な比較では試行回数を増やすことを推奨します。

## 開発目的

このプログラムはゲームそのものをプレイするためのものではなく、
アナログゲームの確率・収入・体力バランスを調整するための
検証ツールとして作成しています。
